# 人工标注辅助系统 —— 详细设计文档

## 版本历史
| 版本 | 日期 | 变更说明 |
|------|------|----------|
| v1.0 | 2026-05-25 | 初始设计：`.sdk-annotations.json` 标注文件 + Pipeline 覆盖层 + Ranker 标注加成 |
| v1.1 | 2026-05-26 | **suppressed 层**：新增 `suppressed.packages`（包路径前缀）和 `suppressed.classes`（类名精确），支持批量压制内部类/模型类，Pipeline 标注为 `layer=suppressed`，rank 权重 0.10；**entry_points 实际落码**；**construction_pattern** 自动检测（无需标注） |

## 1. 背景

### 1.1 问题

启发式角色推断（`_detect_class_role`）覆盖主流 SDK 编码风格，但存在边界场景：
- 部分入口类命名不符合常见模式（非 Manager/Factory/Client 后缀）
- 非标准包结构导致子包匹配失效
- 测试概率低但影响的都是核心入口——一旦入口标错，连锁影响 ranker 排序 + 返回值链展开 + gateway 加成

### 1.2 设计原则

- **增量标注**：默认零标注，启发式照跑；只在需要时标注个别类
- **精确覆盖**：标注直接覆盖启发式结果，不引入新的不确定性
- **单点杠杆**：仅标注 entry_point 即可撬动四个下游模块
- **降级兼容**：标注文件不存在时行为不变，完全向后兼容

## 2. 标注文件格式

### 2.1 文件位置

放在 SDK 源码仓库根目录（与 pom.xml 同级）：

```
repo-dir/
├── pom.xml
├── .sdk-annotations.json    ← 标注文件
└── src/
```

### 2.2 最小标注（推荐起步）

```json
{
  "entry_points": [
    "com.huawei.mateinfo.sdk.file.FileServiceManager"
  ],
  "suppressed": {
    "packages": ["com.huawei.mateinfo.sdk.file.model"]
  }
}
```

仅标注 entry_point 即可联动四个模块。压制 model 包避免大量 Request/Response/DTO 类污染搜索结果。

### 2.3 完整标注（v1.1）

```json
{
  "entry_points": [
    "com.huawei.mateinfo.sdk.file.FileServiceManager",
    "com.huawei.mateinfo.sdk.file.TenantFileServiceManager"
  ],
  "suppressed": {
    "packages": ["com.huawei.mateinfo.sdk.file.model"],
    "classes": ["com.huawei.mateinfo.sdk.file.dao.LocalFileStorageDao"]
  }
}
```

| 字段 | 类型 | 用途 | 优先级 |
|------|------|------|--------|
| `entry_points` | `list[str]` | 指定 SDK 入口类（全限定名） | 高 |
| `suppressed.packages` | `list[str]` | 包路径前缀，该包下所有类标记为 `layer=suppressed` | 高 |
| `suppressed.classes` | `list[str]` | 全限定类名，指定类标记为 `layer=suppressed` | 中 |

注：`construction_pattern` 由 Pipeline 自动检测（`_detect_construction_pattern`），无需标注。`public_apis`/`internal_apis`/`high_layer_methods` 启发式已足够，不再作为标注字段。

## 3. 架构设计

### 3.1 处理流水线

```
parse_java_repo(repo_dir)
  │
  ├─ discover_pom_modules()     → pom 坐标
  ├─ _load_annotations()        → 加载 .sdk-annotations.json（无文件返回 {}）
  │
  └─ for each .java file:
       │
       ├─ parse_java_file(filepath, sdk_meta)
       │   │
       │   ├─ javalang AST 解析
       │   ├─ _detect_class_role()        → heuristic_role
       │   └─ _apply_annotations(fqn, heuristic_role, annotations)
       │        │                              ↑
       │        ├─ 命中 → override_role        │ 差异记日志
       │        └─ 未命中 → heuristic_role ────┘
       │
       └─ _method_to_chunk(..., role, annotation_source)
            └─ meta: {role, annotation_source}
```

### 3.2 核心函数

```python
def _load_annotations(repo_dir: str) -> dict:
    """加载 .sdk-annotations.json。文件不存在时返回 {}。"""
    path = os.path.join(repo_dir, ".sdk-annotations.json")
    if not os.path.exists(path):
        return {}
    with open(path, encoding="utf-8") as f:
        return json.load(f)


def _apply_annotations(
    class_fqn: str,
    heuristic_role: str,
    annotations: dict,
) -> tuple[str, str]:
    """标注覆盖启发式推断 → (final_role, source)。

    source ∈ {"annotation", "heuristic"}
    """
    for role, key in [("entry_point", "entry_points"),
                       ("public_api", "public_apis"),
                       ("internal", "internal_apis")]:
        if class_fqn in annotations.get(key, []):
            if role != heuristic_role:
                logger.info(
                    "role override: %s heuristic=%s → annotation=%s",
                    class_fqn, heuristic_role, role,
                )
            return role, "annotation"

    return heuristic_role, "heuristic"
```

### 3.3 Ranker 标注加成

```python
# 标注来源的 entry_point 比启发式更可靠，额外 +10%
if (item.meta.annotation_source == "annotation"
        and item.meta.role == "entry_point"):
    boost *= 1.10
```

### 3.4 高层方法覆盖

```python
# parse_java_file 中，生成 chunk 时：
override_layer = None
high_methods = annotations.get("high_layer_methods", {}).get(class_fqn, [])
if node.name in high_methods:
    override_layer = "high"

layer = override_layer or _detect_method_layer(...)
```

## 4. 数据流转

### 4.1 chunk meta 新增字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `role` | `str` | 已有：`entry_point` / `public_api` / `internal` |
| `annotation_source` | `str` | 新增：`"annotation"` / `"heuristic"` |

### 4.2 下游消费

```
annotation_source
     │
     ├─ ranker.py   → 标注入口 +10% boost
     ├─ assembler.py → _build_entry_hint() 标注入口提示更确定
     └─ entity.py   → 无变化（entity search 按精确匹配）
```

## 5. 日志与反馈闭环

### 5.1 差异日志

每次标注覆盖启发式时记录 INFO：

```
role override: com.xxx.FileServiceManager heuristic=public_api → annotation=entry_point
```

### 5.2 定期分析

收集差异日志，按模式分组：

```
heuristic=public_api → annotation=entry_point  共 12 个类
  com.xxx.FileServiceManager
  com.xxx.TenantFileServiceManager
  ...

模式提取 → 这些类的共性是什么？启发式规则的哪一步没覆盖到？
       → 据此优化 _detect_class_role 规则
```

## 7. 降级策略

| 场景 | 行为 |
|------|------|
| `.sdk-annotations.json` 不存在 | `_load_annotations()` 返回 `{}`，全走启发式 |
| 文件格式错误 | `json.JSONDecodeError` 被捕获，返回 `{}` |
| 标注的类在源码中不存在 | `_apply_annotations` 不会命中有此 class_fqn 的方法，无影响 |
| `high_layer_methods` 指定了不存在的方法名 | `node.name in [...]` 不会命中，走启发式 |

---

## 8. 与其他模块的关系

- **Pipeline** (`code_parser.py`)：标注加载 + 角色覆盖 + 层级覆盖
- **Ranker** (`ranker.py`)：标注来源的 entry_point 额外加成
- **Assembler** (`assembler.py`)：标注入口提示可更确定（`"此 SDK 通过 FileServiceManager 提供统一入口"`）
- **Entity Search** (`entity.py`)：`class_aliases` 可用于提升别名匹配分数（后续）
- **Orchestrator** (`orchestrator.py`)：无需改动，pipeline 层已处理
